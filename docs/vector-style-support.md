# Mapbox vector style support

KMaP's vector canvas implements part of the [Mapbox Style Specification](https://docs.mapbox.com/style-spec/). Vector tile work is paused pending Compose support for asynchronous measurement and drawing. This table describes the current rendering path. A field being accepted by the JSON model or evaluated by `StyleResolver` does not mean the canvas draws it correctly.

A style is a JSON document containing sources and style layers. The table covers layer types, layer properties, expressions, and root properties from that document.

Supply decoded Mapbox Vector Tiles through `VectorCanvasParameters.tileSource` and pass an `OptimizedStyle` from `StyleResolver`. Each vector canvas has one caller-provided tile source. KMaP does not fetch tiles, sprites, or glyphs from the style document.

| Specification item | Status | Current behavior |
| --- | --- | --- |
| [`source-layer`](https://docs.mapbox.com/style-spec/reference/layers/#source-layer) | Works with the supplied tiles | KMaP looks up an MVT layer by the exact `source-layer` name and reads its features. The name lookup matches the spec. Geometry rendering uses the first MVT layer's extent for every layer in that tile, so layers with different extents are scaled incorrectly. |
| [`source`](https://docs.mapbox.com/style-spec/reference/layers/#source) and style source URLs | No | Mapbox first selects a source by its ID, then selects a `source-layer` inside that source's tiles. KMaP ignores the layer's `source` ID and the style's source URLs. Every layer reads from the canvas's single `tileSource`; it cannot select between sources named in one style. |
| [Layer order](https://docs.mapbox.com/style-spec/reference/root/#layers) | Partial | Non-background layers draw in array order. KMaP draws only the first `background` layer, before the others regardless of its array position. |
| [`background`](https://docs.mapbox.com/style-spec/reference/layers/#background) | Partial | Mapbox has one `background` layer type, which can show a color or a sprite pattern. KMaP draws `background-color` with `background-opacity`, and only over active tile areas. It ignores `background-pattern`, `background-emissive-strength`, and `background-pitch-alignment`; `layout.visibility` is also ignored as described below. |
| [`fill`](https://docs.mapbox.com/style-spec/reference/layers/#fill) | Partial | For polygon features, KMaP reads `fill-color`, `fill-opacity`, and `fill-outline-color`. It combines MVT rings in one path, so correctly wound interior rings cut holes. `fill-opacity` replaces the color's own alpha instead of multiplying it. KMaP draws an outline only when `fill-outline-color` is explicit; Mapbox defaults it to `fill-color`. That outline uses a width of one MVT coordinate before canvas scaling and ignores `fill-opacity`. Antialiasing is always on. KMaP ignores `fill-antialias`, `fill-emissive-strength`, `fill-pattern`, `fill-pattern-cross-fade`, `fill-sort-key`, `fill-translate`, `fill-translate-anchor`, and `fill-z-offset`. |
| `line` | Partial | Line-string rendering reads `line-color`, `line-width`, `line-opacity`, `line-cap`, and `line-join`. Stroke width passes through the tile canvas scale, so `line-width` does not reliably have the spec's pixel units. Polygon geometry in a `line` layer is skipped. Dashes, offsets, patterns, gradients, and other line properties are ignored. |
| `symbol` text | Partial | Draws text for point features. It reads `text-field`, `text-transform`, `text-size`, `text-max-width`, `text-line-height`, `text-justify`, `text-anchor`, `text-offset`, `text-radial-offset`, `text-rotate`, `text-color`, `text-opacity`, `text-halo-color`, `text-halo-width`, `text-halo-blur`, and `text-translate`. Only `text-field` uses actual zoom; the others evaluate at zoom `1`. Without `text-max-width`, text does not wrap, unlike Mapbox's 10 em default. Without `text-line-height`, Compose chooses the spacing instead of Mapbox's 1.2 em default. Positive radial offset moves upward and adds to `text-offset` instead of replacing it; `text-justify: auto` becomes center. Translation and halo dimensions pass through tile scaling; blur uses a shadow approximation. There is no line placement, collision handling, or font selection. |
| `symbol` icons | No | `icon-*` properties are not drawn. The supplied sprite bitmap map is not used. |
| Other [layer types](https://docs.mapbox.com/style-spec/reference/layers/) | No | The vector canvas does not draw `circle`, `raster`, `heatmap`, `hillshade`, `fill-extrusion`, or other layer types. `rasterCanvas` is a separate API; it does not interpret a style's `raster` layer. |
| Layer `filter` | Partial | Expression filters can inspect feature properties, geometry type, and feature ID. They run once when a tile is processed. Their `zoom` context is fixed at `0`; legacy property-name filters such as `["==", "class", "park"]` do not work as Mapbox filters. |
| Layer `minzoom` and `maxzoom` | Partial | KMaP checks each tile's integer zoom when processing non-background layers. It includes tiles at exactly `maxzoom`, while Mapbox hides the layer at that value. The background layer does not use these limits. |
| `layout.visibility` | No | The resolver compiles it, but the renderer never checks it. `"visibility": "none"` does not hide a layer. |
| [Expression operators](https://docs.mapbox.com/style-spec/reference/expressions/) | Partial | The evaluator has branches for `all`, `any`, `!`, comparisons, `get`, `has`, `geometry-type`, `id`, `zoom`, `at`, `in`, `index-of`, `length`, `slice`, `case`, `coalesce`, `match`, `literal`, `to-string`, `typeof`, `concat`, `downcase`, `upcase`, `rgb`, `rgba`, `hsl`, `hsla`, `+`, `-`, `*`, `/`, `step`, and `interpolate`. It does not implement the other operators. A recognized operator only affects the map where the relevant draw path uses its result. In paint and layout, `id` receives the style layer ID instead of the feature ID, and `geometry-type` always sees `Point`. Filters get the actual feature ID and geometry type. |
| Expression semantics | Partial | `get` and `has` only accept a direct property name, `index-of` ignores its optional start index, and unary `-` is unsupported. Array outputs from `interpolate` do not interpolate. Out-of-range `slice` indices can throw. Numeric MVT properties retain their `Long`, `Float`, or `Double` types while style JSON numbers become `Double`: `==`, `match`, and `in` use type-sensitive equality, and numeric draw properties cast to `Double`, so numeric feature values can fail to match or fall back to defaults. |
| Interpolation and color values | Partial | `step` and linear numeric `interpolate` have evaluation paths. Exponential interpolation uses a different curve from Mapbox, cubic Bezier falls back to linear, and interpolated color channels are converted incorrectly. String colors handle hex and comma-form `rgb`/`rgba`/`hsl`/`hsla`; RGB strings require integer channels, and percentage channels and named colors are not parsed. The evaluator converts color-looking strings even in text and comparisons. The `hsl`/`hsla` expression path passes incorrect hue and alpha scales to Compose. Fill, line, and text opacity replace a color's own alpha instead of multiplying it; fill outlines and text halos do not apply their layer opacity. |
| Text field tokens | Partial | `{name}` looks for `name:<resolver locale>` and falls back to `name`; `{name:language}` looks for that language and also falls back to `name`. Other tokens such as `{ref}` remain unchanged. |
| [Glyphs](https://docs.mapbox.com/style-spec/reference/glyphs/) and fonts | No | The style's `glyphs` URL and the font map supplied to `StyleResolver` are not used for labels. The renderer uses Compose's default font. |
| Root camera, lighting, and transitions | No | The model can deserialize `center`, `zoom`, `bearing`, `pitch`, `light`, and `transition`, but these fields do not configure the map or animate style changes. Set the camera through `MapState`. |
| Other root features | No | Imports, terrain, style projection, fog, rain, snow, schema, and similar newer fields have no model or rendering path. |

Unlisted paint and layout properties are ignored. Missing background, fill, and line colors use KMaP's magenta fallback instead of the Mapbox defaults. Loading a style JSON successfully is not a guarantee that it will look like the same style in Mapbox.

## Loading a style file

`Style` models some root, source, and layer fields. Use `Json { ignoreUnknownKeys = true }` to skip unknown fields. Known fields with unsupported shapes still fail to deserialize. For example, Mapbox allows inline GeoJSON in `sources.*.data`, but KMaP models `data` as a string. Deserialization does not validate Mapbox compatibility.
