# Mapbox vector style support

KMaP's vector canvas implements part of the [Mapbox Style Specification](https://docs.mapbox.com/style-spec/). Vector tile work is paused pending Compose support for asynchronous measurement and drawing. This table describes the current rendering path. A field being accepted by the JSON model or evaluated by `StyleResolver` does not mean the canvas draws it correctly.

A style is a JSON document containing sources and style layers. The table covers layer types, layer properties, expressions, and root properties from that document.

Supply decoded Mapbox Vector Tiles through `VectorCanvasParameters.tileSource` and pass an `OptimizedStyle` from `StyleResolver`. Each vector canvas has one caller-provided tile source. KMaP does not fetch tiles, sprites, or glyphs from the style document.

| Specification item | Status | Current behavior |
| --- | --- | --- |
| [`source-layer`](https://docs.mapbox.com/style-spec/reference/layers/#source-layer) | Works with the supplied tiles | KMaP looks up an MVT layer by the exact `source-layer` name and reads its features. The name lookup matches the spec. Geometry rendering uses the first MVT layer's extent for every layer in that tile, so layers with different extents are scaled incorrectly. |
| [`source`](https://docs.mapbox.com/style-spec/reference/layers/#source) and style source URLs | No | Mapbox first selects a source by its ID, then selects a `source-layer` inside that source's tiles. KMaP ignores the layer's `source` ID and the style's source URLs. Every layer reads from the canvas's single `tileSource`; it cannot select between sources named in one style. |
| [Layer order](https://docs.mapbox.com/style-spec/reference/root/#layers) | Partial | Non-background layers draw in array order. KMaP draws only the first `background` layer, before the others regardless of its array position. |
| [`background`](https://docs.mapbox.com/style-spec/reference/layers/#background) | Partial | Mapbox has one `background` layer type, which can show a color or a sprite pattern. KMaP draws `background-color` with `background-opacity`, and only over active tile areas. It ignores `background-pattern`, `background-emissive-strength`, and `background-pitch-alignment`. |
| [`fill`](https://docs.mapbox.com/style-spec/reference/layers/#fill) | Partial | For polygon features, KMaP reads `fill-color`, `fill-opacity`, `fill-outline-color`, and `fill-antialias`. It combines MVT rings in one path, so correctly wound interior rings cut holes. `fill-opacity` multiplies the fill color's alpha and also applies to the outline. With antialiasing enabled, KMaP draws an explicit outline across the boundary or a default outline using `fill-color` only outside the filled area. The outline is one screen pixel wide. KMaP ignores `fill-emissive-strength`, `fill-pattern`, `fill-pattern-cross-fade`, `fill-sort-key`, `fill-translate`, `fill-translate-anchor`, and `fill-z-offset`. |
| [`line`](https://docs.mapbox.com/style-spec/reference/layers/#line) | Partial | Renders line strings and strokes the outer and inner rings of polygons. A `line` style layer can outline the same MVT polygon feature used by a `fill` layer; it does not need a separate line feature. KMaP reads `line-color`, `line-width`, `line-opacity`, `line-cap`, `line-join`, and `line-dasharray`. `line-width` stays in canvas pixels across tile and map scaling, and `line-opacity` multiplies the color's alpha. It supports `butt`, `round`, and `square` caps and `miter`, `round`, `bevel`, and `none` joins. With `line-join: none`, it strokes each segment separately and ignores `line-cap`. Dash lengths are multiples of `line-width` and stay in canvas pixels across scaling; the first and last dashes of an odd-length array join when the pattern repeats. The pattern restarts for each feature, so dashes can break at tile boundaries. Offsets, patterns, gradients, and other line properties are ignored. With `line-pattern`, KMaP still draws `line-color` instead of the pattern and disables dashes. |
| `symbol` text | Partial | Draws text for point features. It reads `text-field`, `text-transform`, `text-size`, `text-max-width`, `text-line-height`, `text-justify`, `text-anchor`, `text-offset`, `text-radial-offset`, `text-rotate`, `text-color`, `text-opacity`, `text-halo-color`, `text-halo-width`, `text-halo-blur`, and `text-translate`. `text-field` uses actual zoom; the others evaluate at zoom `1`. `format` sections can override color, size, and font, and insert supplied sprite bitmaps. The renderer selects a matching font from the map passed to `StyleResolver`, falling back to Compose's default. Without `text-max-width`, text does not wrap, unlike Mapbox's 10 em default. Without `text-line-height`, Compose chooses the spacing instead of Mapbox's 1.2 em default. Positive radial offset moves upward and adds to `text-offset` instead of replacing it; `text-justify: auto` becomes center. Translation and halo dimensions pass through tile scaling; blur uses a shadow approximation. There is no line placement or collision handling. |
| `symbol` icons | Partial | Draws supplied sprite bitmaps for point features through `icon-image` (a name or `image` expression), `icon-size`, `icon-opacity`, `icon-rotate`, `icon-offset`, and `icon-anchor`. The style's sprite URL is not fetched. There is no collision handling, line placement, crossfade, or support for the other icon properties. |
| Other [layer types](https://docs.mapbox.com/style-spec/reference/layers/) | No | The vector canvas does not draw `circle`, `raster`, `heatmap`, `hillshade`, `fill-extrusion`, or other layer types. `rasterCanvas` is a separate API; it does not interpret a style's `raster` layer. |
| Layer `filter` | Partial | Expression filters can inspect feature properties, geometry type, feature ID, and the tile's integer zoom. They run when a tile is processed, so cached tiles retain their original filter result while shown at another map zoom. Legacy property-name filters such as `["==", "class", "park"]` are intentionally unsupported; use `["==", ["get", "class"], "park"]`. |
| Layer `minzoom` and `maxzoom` | Works for rendered layers | KMaP checks the map's current zoom when drawing `fill`, `line`, `symbol`, and the first `background` layer. `minzoom` is inclusive and `maxzoom` is exclusive, including at fractional zoom levels. An omitted `maxzoom` leaves the layer visible at higher zooms. Other layer types are not rendered. |
| `layout.visibility` | Partial | `"none"` hides rendered vector layers and the first `background` layer; an omitted value defaults to visible. Zoom expressions evaluate at integer map zoom. Expression operators have the limitations described below, and other layer types are not rendered. |
| [Expression operators](https://docs.mapbox.com/style-spec/reference/expressions/) | Partial | The evaluator handles `all`, `any`, `!`, comparisons, `get`, `has`, `geometry-type`, `id`, `zoom`, `at`, `in`, `index-of`, `length`, `slice`, `split`, `case`, `coalesce`, `match`, `within`, `literal`, `array`, `boolean`, `number`, `object`, `string`, `to-boolean`, `to-color`, `to-number`, `to-string`, `typeof`, `image`, `format`, `number-format`, `concat`, `downcase`, `upcase`, `rgb`, `rgba`, `hsl`, `hsla`, `to-rgba`, `to-hsla`, `+`, `-`, `*`, `/`, `%`, `^`, `abs`, `ceil`, `floor`, `max`, `min`, `round`, `sqrt`, `acos`, `asin`, `atan`, `cos`, `sin`, `tan`, `e`, `ln2`, `pi`, `ln`, `log10`, `log2`, `step`, `interpolate`, `interpolate-hcl`, and `interpolate-lab`. Other operators, including `feature-state`, `is-supported-script`, `let`, `var`, `properties`, and `line-progress`, remain unsupported. An operator affects rendering only where a drawing path consumes its result. For rendered vector features, paint and layout expressions receive the style layer ID for `id` instead of the feature ID, and `geometry-type` always sees `Point`. Background paint receives an empty ID, while `layout.visibility` receives no ID; filters receive the actual feature ID and geometry type. |
| Expression semantics | Partial | `within` checks point and line features against GeoJSON polygon boundaries in filters. `image` finds names only in the sprite bitmap map supplied to `StyleResolver`; its vector image options and crossfade forms are unsupported. `format` applies section overrides to point labels. `number-format` handles decimal grouping, fractional digits, common currency symbols, and basic locale separators, but it does not implement the full locale, currency, or unit rules of ECMAScript `Intl.NumberFormat`. `get` and `has` only accept a direct property name, `index-of` ignores its optional start index, and unary `-` is unsupported. Array outputs from `interpolate` do not interpolate. Out-of-range `slice` indices can throw. Numeric MVT properties retain their `Long`, `Float`, or `Double` types while style JSON numbers become `Double`: `==`, `match`, and `in` use type-sensitive equality, and some numeric draw properties cast to `Double`, so numeric feature values can fail to match or fall back to defaults. |
| Interpolation and color values | Partial | `step`, numeric `interpolate`, color `interpolate`, and Lab/HCL color interpolation have evaluation paths. The ordinary `interpolate` path still uses a different exponential curve from Mapbox and treats cubic Bezier as linear. String colors handle hex and comma-form `rgb`/`rgba`/`hsl`/`hsla`; RGB strings require integer channels, and percentage channels and named colors are not parsed. Color-looking strings remain strings in text and comparisons; paint properties ending in `-color` convert them to colors. The `hsl`/`hsla` expression path passes incorrect hue and alpha scales to Compose. Text opacity multiplies a color's alpha; text halos do not apply their layer opacity. |
| Text field tokens | Partial | `{name}` looks for `name:<resolver locale>` and falls back to `name`; `{name:language}` looks for that language and also falls back to `name`. Other tokens such as `{ref}` remain unchanged. |
| [Glyphs](https://docs.mapbox.com/style-spec/reference/glyphs/) and fonts | Partial | The style's `glyphs` URL is not fetched. Point labels can use a matching `FontFamily` from the map passed to `StyleResolver` through `text-font` or `format` section overrides; otherwise they use Compose's default font. |
| Root camera, lighting, and transitions | No | The model can deserialize `center`, `zoom`, `bearing`, `pitch`, `light`, and `transition`, but these fields do not configure the map or animate style changes. Set the camera through `MapState`. |
| Other root features | No | Imports, terrain, style projection, fog, rain, snow, schema, and similar newer fields have no model or rendering path. |

Unlisted paint and layout properties are ignored. Missing background, fill, and line colors use KMaP's magenta fallback instead of the Mapbox defaults. Loading a style JSON successfully is not a guarantee that it will look like the same style in Mapbox.

## Loading a style file

`Style` models some root, source, and layer fields. Use `Json { ignoreUnknownKeys = true }` to skip unknown fields. Known fields with unsupported shapes still fail to deserialize. For example, Mapbox allows inline GeoJSON in `sources.*.data`, but KMaP models `data` as a string. Deserialization does not validate Mapbox compatibility.
