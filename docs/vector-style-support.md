# Vector style support

KMaP's vector style model is based on the [Mapbox Style Specification](https://docs.mapbox.com/style-spec/) and the [MapLibre Style Specification](https://maplibre.org/maplibre-style-spec/). It supports many constructs shared by both, while the vector canvas renders a subset with the differences listed below. Vector tile work is paused pending Compose support for asynchronous measurement and drawing. This table describes the current rendering path. A field being accepted by the JSON model or evaluated by `StyleResolver` does not mean the canvas draws it correctly.

A style is a JSON document with style layers and, in Mapbox and MapLibre styles, source definitions. The table covers layer types, layer properties, expressions, and root properties from that document.
KMaP accepts a subset with only `layers` at the root. In `Style`, an omitted `version` is `null` and omitted `sources` is an empty map. `CompiledStyle` retains neither field.

Supply decoded Mapbox Vector Tiles through `VectorCanvasParameters.tileSource` and pass a `CompiledStyle` from `StyleResolver`. Each vector canvas has one caller-provided tile source. KMaP does not fetch tiles, sprites, or glyphs from the style document. Supply decoded sprite images with their `pixelRatio` and `sdf` metadata through `StyleResolver`'s `sprites` parameter. `decodeSpriteAtlas` extracts them from a matching sprite JSON/PNG pair; the demo loads its packaged atlases this way.

| Specification item | Status | Current behavior |
| --- | --- | --- |
| [`source-layer`](https://docs.mapbox.com/style-spec/reference/layers/#source-layer) | Works with the supplied tiles | KMaP looks up an MVT layer by the exact `source-layer` name and reads its features. It reports and omits `fill`, `line`, and `symbol` layers without this field; `background` does not need it. Geometry rendering uses the first MVT layer's extent for every layer in that tile, so layers with different extents are scaled incorrectly. |
| [`source`](https://docs.mapbox.com/style-spec/reference/layers/#source) and style source URLs | No | Mapbox first selects a source by its ID, then selects a `source-layer` inside that source's tiles. KMaP ignores the layer's `source` ID and the style's source URLs. Every layer reads from the canvas's single `tileSource`; it cannot select between sources named in one style. |
| [Layer order](https://docs.mapbox.com/style-spec/reference/root/#layers) | Partial | Non-background layers draw in array order. KMaP draws only the first `background` layer, before the others regardless of its array position. |
| [`background`](https://docs.mapbox.com/style-spec/reference/layers/#background) | Partial | KMaP draws `background-color` or a supplied `background-pattern` with `background-opacity`, only over active tile areas. The pattern repeats from a shared map origin. A missing pattern image leaves the background undrawn. It ignores `background-emissive-strength` and `background-pitch-alignment`. |
| [`fill`](https://docs.mapbox.com/style-spec/reference/layers/#fill) | Partial | For polygon features, KMaP reads `fill-color`, `fill-opacity`, `fill-outline-color`, `fill-antialias`, and supplied `fill-pattern` images. It combines MVT rings in one path, so correctly wound interior rings cut holes. A pattern repeats from a shared map origin, preserves holes, applies `fill-opacity`, and replaces the fill color and outline; a missing pattern image leaves the polygon undrawn. Without a pattern, `fill-opacity` multiplies the fill color's alpha and also applies to the outline. With antialiasing enabled, KMaP draws an explicit outline across the boundary or a default outline using `fill-color` only outside the filled area. The outline is one screen pixel wide. It ignores `fill-emissive-strength`, `fill-pattern-cross-fade`, `fill-sort-key`, `fill-translate`, `fill-translate-anchor`, and `fill-z-offset`. |
| [`line`](https://docs.mapbox.com/style-spec/reference/layers/#line) | Partial | Renders line strings and strokes the outer and inner rings of polygons. A `line` style layer can outline the same MVT polygon feature used by a `fill` layer; it does not need a separate line feature. KMaP reads `line-color`, `line-width`, `line-opacity`, `line-cap`, `line-join`, and `line-dasharray`. `line-width` uses logical screen pixels across tile and map scaling, with display density applied. `line-opacity` multiplies the color's alpha. It supports `butt`, `round`, and `square` caps and `miter`, `round`, `bevel`, and `none` joins. With `line-join: none`, it strokes each segment separately and ignores `line-cap`. Dash lengths are multiples of `line-width` and account for display density across scaling; the first and last dashes of an odd-length array join when the pattern repeats. The pattern restarts for each feature, so dashes can break at tile boundaries. Offsets, patterns, gradients, and other line properties are ignored. With `line-pattern`, KMaP still draws `line-color` instead of the pattern and disables dashes. |
| `symbol` text | Partial | Draws plain text for point features. It reads `text-field`, `text-transform`, `text-size`, `text-max-width`, `text-line-height`, `text-justify`, `text-anchor`, `text-offset`, `text-radial-offset`, `text-rotate`, `text-color`, `text-opacity`, `text-halo-color`, `text-halo-width`, `text-halo-blur`, and `text-translate`. Set `paint.text-color` to color the entire label; formatted text sections are unsupported. Text layout properties other than `text-size`, including `text-field`, evaluate at integer map zoom; `text-size` and text paint properties evaluate at fractional map zoom. Text size stays in screen pixels while the map scales. The renderer selects a matching font from the map passed to `StyleResolver`, falling back to Compose's default. Without `text-max-width`, text does not wrap, unlike Mapbox's 10 em default. Without `text-line-height`, Compose chooses the spacing instead of Mapbox's 1.2 em default. Positive radial offset moves upward and adds to `text-offset` instead of replacing it; `text-justify: auto` becomes center. Text halo width and blur account for tile scale, map scale, and display density; blur still uses a shadow approximation. Translation still passes through tile scaling. There is no line placement or collision handling. |
| `symbol` icons | Partial | Draws supplied sprite images for point features through `icon-image` (a name or `image` expression), `icon-size`, `icon-opacity`, `icon-rotate`, `icon-offset`, and `icon-anchor`. Sprite `pixelRatio` sets the logical image size; display density applies to icon dimensions and offsets while tile and map scale leave them stable. SDF images use `icon-color` (default black), `icon-halo-color` (default transparent), `icon-halo-width`, and `icon-halo-blur`; `icon-opacity` multiplies both the icon and halo alpha. Halo width zero draws no halo. Halo width and blur use logical screen pixels relative to `icon-size`, with display density applied, within the sprite's SDF padding. Correct pixel widths assume an SDF generated with an eight-pixel distance range multiplied by its `pixelRatio`. ColorMatrix approximates MapLibre's smoothstep edge with a linear transition. Ordinary bitmap sprites retain their colors and ignore halo properties. Other icon paint effects remain unsupported. The style's sprite URL is not fetched. There is no collision handling, line placement, or crossfade. |
| Other [layer types](https://docs.mapbox.com/style-spec/reference/layers/) | No | The resolver reports and omits `circle`, `raster`, `heatmap`, `hillshade`, `fill-extrusion`, and other unsupported types from `CompiledStyle`. `rasterCanvas` is a separate API; it does not interpret a style's `raster` layer. |
| Layer `filter` | Partial | Expression filters can inspect feature properties, geometry type, feature ID, and the tile's integer zoom. They run when a tile is processed, so cached tiles retain their original filter result while shown at another map zoom. Legacy property-name filters such as `["==", "class", "park"]` are reported as unsupported and match no features; use `["==", ["get", "class"], "park"]`. |
| Legacy style functions | No | Object functions such as `{"stops": [[0, 1], [10, 2]]}` are reported as unsupported. Use `step` or `interpolate` expressions instead. |
| Layer `minzoom` and `maxzoom` | Works for rendered layers | KMaP checks the map's current zoom when drawing `fill`, `line`, `symbol`, and the first `background` layer. `minzoom` is inclusive and `maxzoom` is exclusive, including at fractional zoom levels. An omitted `maxzoom` leaves the layer visible at higher zooms. Other layer types are not rendered. |
| `layout.visibility` | Partial | `"none"` hides rendered vector layers and the first `background` layer; an omitted value defaults to visible. Zoom expressions evaluate at integer map zoom. Expression operators have the limitations described below, and other layer types are not rendered. |
| [Expression operators](https://docs.mapbox.com/style-spec/reference/expressions/) | Partial | The evaluator handles `all`, `any`, `!`, comparisons, `get`, `has`, `geometry-type`, `id`, `zoom`, `at`, `in`, `index-of`, `length`, `slice`, `split`, `case`, `coalesce`, `match`, `within`, `literal`, `array`, `boolean`, `number`, `object`, `string`, `to-boolean`, `to-color`, `to-number`, `to-string`, `typeof`, `image`, `number-format`, `concat`, `downcase`, `upcase`, `rgb`, `rgba`, `hsl`, `hsla`, `to-rgba`, `to-hsla`, `+`, `-`, `*`, `/`, `%`, `^`, `abs`, `ceil`, `floor`, `max`, `min`, `round`, `sqrt`, `acos`, `asin`, `atan`, `cos`, `sin`, `tan`, `e`, `ln2`, `pi`, `ln`, `log10`, `log2`, `step`, `interpolate`, `interpolate-hcl`, and `interpolate-lab`. Other operators, including `format`, `feature-state`, `is-supported-script`, `let`, `var`, `properties`, and `line-progress`, remain unsupported. An operator affects rendering only where a drawing path consumes its result. Paint and layout expressions for vector features receive the feature ID when present and its geometry type. Background paint and `layout.visibility` have no feature ID; filters also receive the feature ID and geometry type. |
| Expression semantics | Partial | `within` checks point and line features against GeoJSON polygon boundaries in filters, including when those features come from vector tiles. `image` finds names only in the sprite image map supplied to `StyleResolver`; its vector image options and crossfade forms are unsupported. `coalesce` returns the first non-null result; when every image is missing, KMaP returns `null`, while Mapbox can return the first unresolved image. `number-format` handles decimal grouping, fractional digits, common currency symbols, and basic locale separators, but it does not implement the full locale, currency, or unit rules of ECMAScript `Intl.NumberFormat`. `get` and `has` accept calculated property names and an optional object. `index-of` uses its optional start index; `index-of`, `length`, and `slice` count UTF-16 surrogate pairs as one string position. Unary `-` negates numbers, `slice` handles negative and out-of-range indices, and `interpolate` blends numeric arrays component by component. Arithmetic operators require numeric operands: use `to-number` to convert a numeric string explicitly. Numeric MVT properties retain their `Long`, `ULong`, `Float`, or `Double` types; MVT `uint64` feature IDs and values keep all 64 bits. Style JSON numbers become `Double`, which cannot express every integer above 2^53 exactly; use another feature value for an exact numeric comparison or `to-string` for exact text. Comparisons, membership, matching, and numeric draw properties accept these numeric types. |
| Interpolation and color values | Partial | `step` and `interpolate` evaluate numeric, numeric-array, and color outputs. Linear, exponential, and cubic Bezier curves apply to ordinary and Lab/HCL color interpolation. String colors recognize hex, comma-form `rgb`/`rgba`/`hsl`/`hsla`, RGB percentages, and CSS named colors. Color-looking strings remain strings in text and comparisons; paint properties ending in `-color` convert them to colors. `hsl`/`hsla` expressions use degree hue and fractional alpha. `text-opacity` multiplies both text and halo color alpha. The inspector checks argument counts and obvious numeric, string, and boolean literal operands for many supported operators. It does not infer feature-property types or fully validate every expression; malformed inputs may still evaluate to null or a fallback. |
| Text and icon tokens | No | Literal `text-field` and `icon-image` strings containing `{property}` are reported as unsupported and are not drawn. Use `get` and `to-string` for labels, `concat` for combined text, and `image` for sprite names. Missing values convert to an empty string. Strings inside expressions remain literal. Icons still require a matching supplied sprite image. |
| [Glyphs](https://docs.mapbox.com/style-spec/reference/glyphs/) | No | The style's `glyphs` URL is not fetched. |
| [`text-font`](https://docs.mapbox.com/style-spec/reference/layers/#text-font) | Partial | Point labels use the first matching `FontFamily` from the map passed to `StyleResolver`; otherwise they use Compose's default font. The demo supplies local fonts for the 21 names in its bundled styles. KMaP does not fall back to another listed font for individual characters. |
| Root camera, lighting, and transitions | No | The model can deserialize `center`, `zoom`, `bearing`, `pitch`, `light`, and `transition`, but these fields do not configure the map or animate style changes. Set the camera through `MapState`. |
| Other root features | No | Imports, terrain, style projection, fog, rain, snow, schema, and similar newer fields have no model or rendering path. |

Unlisted paint and layout properties are ignored. Missing background, fill, and line colors use KMaP's magenta fallback instead of the Mapbox defaults. Loading a style JSON successfully is not a guarantee that it will look like the same style in Mapbox.

## Loading and checking a style file

Pass the original JSON to `StyleResolver` to get a `StyleResolution` with the compiled `style` and a list of `issues`:

```kotlin
val result = StyleResolver().resolve(styleJson)
result.issues.forEach { issue ->
    println("${issue.kind}: ${issue.path}: ${issue.message}")
}
val style = result.style ?: error("Style JSON could not be loaded")
```

Each issue includes a JSON path and, for layer issues, a layer ID. `UNSUPPORTED` means KMaP recognizes a construct it does not render or evaluate; `UNKNOWN` means a root, source, or layer field is not recognized; `INVALID` means the JSON could not be decoded, a supported property's literal has the wrong type, or an inspected expression has invalid arguments. For example, `"fill-opacity": "half"`, `"line-width": ["/", 8, 2, 2]`, and `"line-width": ["+", "3", 2]` produce `INVALID` issues. The resolver does not log automatically. A style can compile while some fields have issues. An empty issue list means this inspection found no unsupported constructs or invalid literals or arguments covered by its checks; it does not promise the same appearance as Mapbox. Pass the original JSON string to the resolver. Fields discarded by a separate deserializer cannot be reported. Known fields with unsupported shapes still fail to decode; for example, inline GeoJSON in `sources.*.data` is allowed by Mapbox but modeled as a string by KMaP.
